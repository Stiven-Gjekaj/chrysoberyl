<objective>
Let a producer name a region, and make the engine register inside that region
instead of searching for it, without changing the engine.

`RegionHint` and `Frame.hints` have existed since phase 1 and nothing writes
or reads them. This plan fills both ends: a sidecar file a producer writes,
and a crop that hands the unmodified `compare` a smaller frame. The engine is
told where to look rather than asked to find it, and it never had to change
to be told.

Purpose: SRC-09. The alternative design, constraining the registration search
window inside `chrys-core`, would work and would touch the engine in a phase
whose headline claim is that it does not. This design avoids the tension
rather than arguing it away.

Output: `Frame::crop_to_region`, a `<stem>.hints.toml` reader, a `--region`
flag, a committed hinted fixture, and a test that shows the two answers
differ.
</objective>

**Crop.** Add
`pub fn crop_to_region(&self, hint: &RegionHint) -> Result<Frame, RegionOutOfBounds>`
to `Frame` in `crates/chrys-source/src/lib.rs`. It validates the rectangle
against the frame's own width and height, using checked arithmetic so a hint
near `u32::MAX` cannot wrap into a rectangle that appears to fit, and returns
an error when it does not fit or when its width or height is zero. Otherwise
it copies the named rows and columns into a new RGBA8 buffer with no padding,
keeps the source frame's `index`, and returns a frame with an empty `hints`
list, because a cropped frame's coordinate space is not the one the original
hints were written in.

Keep this crate free of dependencies. Its own module header states that it
depends on nothing outside the standard library, and `chrys-core` depends on
it, so a dependency added here lands in the engine's graph. Define
`RegionOutOfBounds` as a plain struct carrying the hint's name, its
rectangle and the frame's size, with `Display` and `std::error::Error`
implemented by hand rather than derived through `thiserror`. That is about
fifteen lines and it costs the engine's dependency graph nothing.

**Sidecar.** Create `crates/chrys-source-raster/src/hints.rs` with
`pub fn read_hints_sidecar(image_path: &Path) -> Result<Vec<RegionHint>, RasterError>`.
It looks for a file whose name is the image's stem plus `.hints.toml`, in the
same directory. A missing file returns an empty vector, because most sources
supply no hint and that is not an error. A present file is parsed with `toml`
and `serde`, added to the workspace dependency table as `toml = "=1.1.5"` and
`serde = { version = "=1.0.229", features = ["derive"] }` and taken by this
crate. The document holds an array of tables named `hint`, each with `name`,
`x`, `y`, `width` and `height`:

```toml
[[hint]]
name = "logo"
x = 64
y = 64
width = 128
height = 128
```

Deserialize into private structs declared in this file, then convert into
`chrys_source::RegionHint` with a `From` impl. Do not derive `Deserialize` on
`RegionHint` itself: that would put `serde` in `chrys-source`, and therefore
in the engine's dependency graph, for a sidecar parser the engine never
reads. `02-RESEARCH.md` Q6 recommended the derive; this plan takes the other
route for that reason, and its open question about a matching `Serialize`
dissolves with it. Extend `RasterError` with a variant for a malformed
sidecar that carries the path and the parser's own message, which `toml`
reports with a line and column.

Call `read_hints_sidecar` from `RasterSource::load`, replacing the
`hints: Vec::new()` it writes today. Call it from
`crates/chrys-source-sequence/src/sequence.rs` too, once per frame, keyed on that
frame's own file, so a sequence gets per-frame hints through the same
function. One function, called from both adapters, is what stops this from
becoming a per-format special case.

**Fixture.** Extend `crates/chrys-source-raster/examples/make-fixtures.rs`
with `write_hint_01()`, writing `tests/golden/hint-01/base.png`,
`base.hints.toml`, `candidate.png` and `candidate.hints.toml`. Build the pair
so the two comparisons disagree, which is the whole point: a 128x128 region at
(64, 64) holds identical content on both sides, and the rest of the canvas is
shifted by six pixels on the candidate side, so the whole-frame comparison
reports something and the region comparison reports `identical`. Fill the
named region with at least four distinct rectangles of different colours and
sizes, not a flat block: phase 1 recorded that a flat region gives a
correlation search nothing to hold, and `BLOCK_SIDE` is 32, so a 128x128
region gives the block match sixteen blocks to work with and the region needs
edges inside it. Write both sidecars with the same `logo` region, so a hint is
matched by name across the two sides rather than by position. Commit the four
files.

**CLI.** Add `--region <NAME>` to the `compare` subcommand. When it is
absent, nothing changes. When it is present, for every frame index, find a
hint with that name in the base frame and in the candidate frame, crop both
through `crop_to_region`, and pass the two cropped frames to the existing
`compare_sequence`. Do not touch `compare_sequence` or anything it calls; the
engine receives smaller frames and runs exactly the code it runs today.
Fail loudly when either side has no hint of that name, naming which side and
listing the names that side does carry, so a person who mistyped a region
learns the available ones instead of a bare refusal.

A sidecar is a file this project's own code did not write, so it is untrusted
input on the same terms as an image. Phase 1 set the standard: a corrupt,
truncated, empty or missing file is reported with a specific message and a
non-zero exit, never a crash and never a silent repair. Meet that standard
here.

Add the out-of-bounds tests to `crates/chrys-source/src/lib.rs`'s own test
module: a hint wider than the frame, a hint taller than the frame, a hint
whose origin sits outside the frame, a hint whose `x + width` overflows a
`u32`, and a hint of zero width. Each returns `RegionOutOfBounds` and never
panics and never clamps. Assert on the message too, not only the variant: it
names the region, its rectangle and the frame's size, because a person
holding a refusal needs to know which of the two is wrong.

Harden the sidecar parser in `crates/chrys-source-raster/src/hints.rs`. Set
`deny_unknown_fields` on the deserialized structs, so a misspelled key is a
loud failure rather than a hint that silently does not exist. That matters
more here than it looks: a sidecar with `w` where `width` belongs would
otherwise parse into a default and crop the wrong rectangle. Add tests
covering invalid TOML, an unknown key, a negative coordinate and a
non-integer coordinate. Each writes a temporary file, calls the reader,
asserts the error variant, and asserts the message carries the parser's own
position, the way `toml` reports it. Build each temporary file inside the
test rather than committing a corpus of broken files; the state a test needs
belongs in the test.

Add one more test that is about this project rather than about TOML: a
sidecar naming two regions with the same name. Decide and state the rule, and
implement it: the reader refuses a duplicate name, because a hint is looked
up by name and two answers to one name is a question the tool cannot answer.
Say so in the error message.
