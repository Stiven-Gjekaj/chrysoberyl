<objective>
Make the sequence the only unit of comparison, and compare one numbered
frame sequence pair end to end.

Phase 1 built `compare(base: &Frame, candidate: &Frame)`. This plan moves
that whole pipeline into `compare_sequence(&[Frame], &[Frame])` and turns
`compare` into a thin wrapper over it. Every later format family that
arrives as an ordered set of frames, and every one of them is such a set,
then meets one entry point instead of choosing between two.

Purpose: SRC-02 needs a sequence pair compared frame by frame. SRC-08 needs
the next input family to arrive with no engine change, and that only holds
if the generic pairing code lands now, in this wave, where a `chrys-core`
change is still allowed.

Output: a new `sequence` module in the engine, a new `chrys-source-sequence`
adapter crate, a committed 11-frame fixture pair with non-padded filenames,
and a CLI that dispatches a directory to the sequence adapter.
</objective>

**Engine.** Create `crates/chrys-core/src/sequence.rs` and register it in
`crates/chrys-core/src/lib.rs` with `pub mod sequence;` and
`pub use sequence::compare_sequence;`. Move the entire body of the existing
`compare` function, verbatim, out of `lib.rs` and into a private
`fn compare_pair(base: &Frame, candidate: &Frame) -> Result<Verdict, CompareError>`
in the new module. Move the doc comment with it. Nothing in the moved body
changes: the same shape check, the same registration, the same confidence
test, the same block match, the same suppression, the same labelling, in the
same order. Add
`pub fn compare_sequence(base: &[Frame], candidate: &[Frame]) -> Result<Vec<Verdict>, CompareError>`
in the same module. It checks, in this order: either side empty returns
`Ok(vec![Verdict::Refused { reason: RefusalReason::EmptySequence }])`;
unequal lengths return
`Ok(vec![Verdict::Refused { reason: RefusalReason::FrameCountMismatch { base: base.len(), candidate: candidate.len() } }])`;
otherwise it zips the two slices and maps `compare_pair` over every index,
collecting into `Result<Vec<Verdict>, CompareError>`.

Both refusal variants are new. Add them to `RefusalReason` in
`crates/chrys-core/src/verdict.rs`, alongside the existing
`DimensionMismatch` and `PeakConfidenceTooLow`, and extend the existing
`Display` impl for both, because that match is exhaustive and the crate does
not compile without them. The count-mismatch sentence names both counts and
states that this engine pairs by index and does not pair a prefix or
interpolate. The empty sentence states that a side decoded to no frame at
all. Keep both in the register of the existing refusal text: short, active,
present tense, and enough for a reader to know what to fix. Add the two
matching unit tests in `sequence.rs`'s own `#[cfg(test)]` module in this same
commit, one for each variant, each asserting that the returned vector holds
exactly one verdict and that the refusal text names the numbers it carries.
Build every test frame in memory, so the engine keeps the dependency graph it
declares.

Then reduce `compare` in `crates/chrys-core/src/lib.rs` to a wrapper with an
unchanged signature: it calls
`sequence::compare_sequence(std::slice::from_ref(base), std::slice::from_ref(candidate))?`
and returns the first element of the returned vector. A one-against-one
sequence can reach neither the empty check nor the count check, so the vector
always holds exactly one verdict; handle the impossible empty vector by
returning `Ok(Verdict::Refused { reason: RefusalReason::EmptySequence })`
rather than by unwrapping or panicking, because an engine that produced no
verdict is a refusal and this project never panics on a path a caller can
reach. Do not leave a second copy of the pipeline behind in `lib.rs`. There
is one implementation and `compare` is its wrapper.

**Adapter.** Create the crate `crates/chrys-source-sequence`, picked up by
the existing `crates/*` workspace member glob with no workspace manifest
edit. It declares `#![forbid(unsafe_code)]` and `[lints] workspace = true`,
and depends on `chrys-source` (path), `chrys-source-raster` (path),
`thiserror` (workspace) and `natord`, which you add to the workspace
dependency table in the root `Cargo.toml` as `natord = "=1.0.9"`, pinned
exactly like every other dependency in that table. Define
`SequenceLimits { max_frames: usize, max_total_pixels: usize }` with
`Default` returning `max_frames: 512` and `max_total_pixels: 134_217_728`;
document that the pixel budget is the 512 MiB of
`DecodeLimits::default().max_alloc` divided by the four bytes an RGBA8 pixel
occupies, so a directory of a thousand small files cannot do what a single
oversized file already cannot. Define `SequenceSource` holding a
`SequenceLimits` and a `DecodeLimits`, with `new()`, `with_limits(..)` and a
`Default` impl. Define `SequenceError` with `thiserror`, carrying at least:
the directory could not be read; the directory holds no file; the frame count
exceeds `max_frames`; the cumulative pixel count exceeds `max_total_pixels`;
and a decode failure that names the exact file and wraps the underlying
`RasterError`. Those three types and the `Source` impl live in `src/lib.rs`.

Put the listing, the sort and the per-file decode in a module of their own,
`src/sequence.rs`, declared from `lib.rs` with `mod sequence;`, so the
natural-sort test addresses as `sequence::tests::sorts_by_natural_order`,
which is the name `02-VALIDATION.md`'s test map already commits this phase to.
The module reads the immediate entries of the directory with
`std::fs::read_dir`, keeps only entries whose metadata reports a regular
file, does not recurse, sorts the retained paths by `natord::compare` over
the file name unconditionally with no branch that decides a name looks
padded, then decodes each file in sorted order through
`chrys_source_raster::decode::decode_guarded` followed by
`chrys_source_raster::normalize::normalize_to_rgba8`. It opens no
`image::ImageReader` of its own; the guarded entry point is the only decode
path this crate has, and a second one is a second place the memory limit can
be forgotten. It assigns `index` from the sorted position, sets `hints` to
`Vec::new()` for now, and fails loudly naming the file when one entry does
not decode rather than skipping it.

## Trust Boundaries

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Denial of Service | `SequenceSource::load` | high | mitigate | A sequence multiplies phase 1's per-file limit by the file count, so a thousand small frames is the new shape of the same bomb. `SequenceLimits::max_frames` (512) stops the count, and `max_total_pixels` (134,217,728, the 512 MiB `DecodeLimits` allowance at four bytes per pixel) stops the cumulative allocation.
