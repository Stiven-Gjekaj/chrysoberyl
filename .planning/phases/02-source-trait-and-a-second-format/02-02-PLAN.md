<objective>
Prove that the engine now has one comparison pipeline, and that moving it
did not move a single byte of phase 1's output.

Plan 02-01 relocated the whole pipeline and made `compare` a wrapper. Two
things can silently undo that later: someone reintroduces a second pipeline
in `lib.rs`, and someone changes the moved code in a way that shifts a
digest. This plan makes the first a red test and the second a committed
regression fixture. It also teaches `--hash-only` to report a sequence, which
is what the six-runner matrix needs in plan 02-04.

Purpose: SRC-08's claim is that a new input family costs the engine nothing.
That claim is only checkable if the engine's one pipeline is a guarded fact
rather than a habit.

Output: a sixth guard in the engine's determinism test file, a committed
four-line digest fixture with a test that reads it, and a per-index digest
report.
</objective>

Add a sixth guard to `crates/chrys-core/tests/determinism.rs`, named
`the_engine_has_one_comparison_pipeline_and_compare_delegates_to_it`. It
lives here, next to the dependency guard, for two reasons: it is the same
kind of invariant, an architectural fact checked at the source level rather
than at runtime, and the CI `guards` job already runs this exact test target,
so the guard costs no new workflow wiring.

Reuse the file's own helpers rather than writing new scanning code:
`rust_files_under(src_dir())` to list the engine's sources,
`strip_comments_and_strings` so a doc comment or a string literal cannot
satisfy or trip the guard, and `find_substring_occurrences` for the matches.
The learning from phase 1 that a helper in a test module violated the rule
the module enforces applies here too: scan the whole file, not only its
production paths.

Define a private constant in the test file listing the entry points of the
comparison pipeline: the registration call the pipeline opens with, the peak
index, the confidence assessment, the block match, the antialiasing
suppression and the region labelling. Take the exact identifiers from the
`pub use` lines of `crates/chrys-core/src/register/mod.rs` and
`crates/chrys-core/src/classify/mod.rs`, so the constant names real symbols
rather than approximations of them.

The guard asserts three facts.

First, `crates/chrys-core/src/sequence.rs`'s stripped text holds every one of
the six entry points. That is the file that owns the pipeline, and a guard
that only bans copies elsewhere would stay green if the original were gutted.

Second, no other file under `crates/chrys-core/src/` holds four or more of
the six. Exclude the modules that define these symbols, which is anything
under `src/register/` and `src/classify/`. Four is the threshold rather than
one because `crates/chrys-core/src/residual.rs` legitimately calls two of
them: `residual_rgba8` runs its own registration to build the residual buffer
for the digest, and that is existing, correct code this guard must not
declare a defect. Read that file before you set the constant, and record in
the summary which two it uses, so a later reader knows the threshold was
measured against the tree and not chosen to make a test pass. On failure the
panic message names every offending file and lists which entry points it
holds, so a reader learns where a second pipeline grew rather than only that
a count was wrong.

Third, `crates/chrys-core/src/lib.rs`'s stripped text holds at least one
occurrence of `compare_sequence` and none of the six entry points, so
`compare` cannot quietly stop delegating and cannot regrow the pipeline in
the crate root. On failure the message states which of the two halves broke,
and names the decision it breaks: the sequence is the only unit, and
`compare` is its wrapper.

Do not add this guard to `scripts/determinism-drill.sh`. That script drills
the three determinism guards phase 1 shipped, and plan 02-04 owns the drill
for this phase's own boundary claim. Prove this guard here instead, by hand
and inside a disposable worktree, and record the two runs verbatim in the
summary: add the six-line call chain to a copy of `lib.rs`, confirm the guard
goes red and names `lib.rs`, then restore and confirm it goes green again. A
guard nobody has seen fail is a belief, not a guard.
