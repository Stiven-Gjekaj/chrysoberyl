Purpose: DET-05 is a statement about what the binary can do, not about
what the code happens to call, so the check that carries it reads the
resolved feature graph. SRC-04's adapter reads an untrusted XML document

## The engine boundary anchor

`c97a6fb778c4b1373e5c4dc563481cc18e4c98c0` is `crates/chrys-core`'s tree
object id, read at planning time from `HEAD` at commit `199477d`. It must
not move.

That id covers `crates/chrys-core/tests/` as well as its `src/`. So the
two guards this plan adds cannot be written into
`crates/chrys-core/tests/determinism.rs`, where `DENIED_DEPENDENCY_CRATES`
already lives and where they would otherwise belong. They live in
`chrys-cli` instead, which is the crate that already depends on every
other one, and which already hosts `unsafe_guard.rs` and
`decode_limits_guard.rs` for exactly this stated reason. Read either of
those files' own header comments before writing a third.

The practical consequence: `DENIED_DEPENDENCY_CRATES` names `image`,
`png`, `gif` and the rest, and it will never name `resvg`. A guard that
covers the four new crates has to live somewhere else, and Task 2 is where
it lives.

**A deliberate deviation from the validation contract, recorded here so it

Stripping matters here for a specific reason. Every plan, research
