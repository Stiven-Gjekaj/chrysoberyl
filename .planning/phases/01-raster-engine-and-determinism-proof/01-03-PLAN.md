**As a** person who reviews visual changes, **I want to** compare two raster
images and read a structural verdict, **so that** the verdict is byte-identical
on every operating system and CPU architecture.

<objective>
Build the determinism guard while the engine is still thin, exactly as the
research asks. A determinism bug found against one format and a tracer engine is
tractable. The same bug found after six formats and a GPU mirror exist is not.

Purpose: this plan creates the mechanism, not the proof. The mechanism is a
digest report over raw RGBA8 bytes, a workflow that runs it on six runner
labels, and a job that compares the six results. Plan 01-08 then watches that
guard go red on purpose, because a guard nobody has seen fail is not a guard.

Output: `chrys compare ... --hash-only`, a committed decode digest, and
`.github/workflows/determinism.yml`.

**Honest scope note.** PROJECT.md records that this repository goes to no remote
until the author asks. The six-runner matrix therefore cannot run during this
phase. This plan writes and locally validates the workflow, and proves the inner
command on this host. The green matrix is recorded as a human check and is
harvested at the end of the phase. Plan 01-08 supplies the cross-architecture
evidence that can be measured today, on one machine.
</objective>

Add `sha2` from the workspace dependency table to `crates/chrys-core/Cargo.toml`.

Write `crates/chrys-core/src/residual.rs` with
`pub fn residual_rgba8(base: &Frame, candidate: &Frame) -> Result<Vec<u8>, CompareError>`.
It returns an RGBA8 buffer of the same length as the inputs, where each of the
red, green and blue bytes is the absolute difference of the corresponding input
bytes and the alpha byte is 255. It returns `CompareError::ShapeMismatch` when
the frames differ in size. Put a doc comment on it stating that plan 01-06
replaces the body with the real residual field and keeps this signature, so the
digest contract does not move.

Write `crates/chrys-core/src/hash.rs` with three public items.
`rgba8_digest(bytes: &[u8]) -> String` returns the SHA-256 of the bytes as 64
lowercase hexadecimal characters. `DigestSet` is a struct with four `String`
fields: `decode_base`, `decode_candidate`, `residual` and `verdict`.
`digest_report(base: &Frame, candidate: &Frame, verdict: &Verdict) -> Result<DigestSet, CompareError>`
builds the set: the first two fields digest `Frame::rgba8` of each input, the
third digests `residual_rgba8`, and the fourth digests the UTF-8 bytes of the
`Display` form of the verdict. Give `DigestSet` a `Display` that prints the four
lines in that fixed order, each as the label, one space, and the digest.

Write the digest-input contract as a doc comment at the top of `hash.rs`, in
five sentences: the digest covers raw RGBA8 bytes as they sit in memory; the
digest never covers a re-encoded file, because an encoder is a second variable;
the digest never covers a path, a timestamp or a host name, because those are
not properties of the comparison; the byte order is the `Frame` row-major,
straight-alpha layout; and any change to this contract invalidates every
committed digest in the repository.

Add `pub mod hash;` and `pub mod residual;` to `crates/chrys-core/src/lib.rs`,
and add a `ShapeMismatch` variant to `CompareError`.

Add a `--hash-only` boolean flag to the `compare` subcommand in
`crates/chrys-cli/src/main.rs`. When it is set, the command loads both frames,
runs `compare`, builds the digest set, prints its `Display` form to stdout, and
exits 0. An error still exits 3. When the flag is absent the behaviour is
unchanged.

Generate `tests/golden/pair-01/expected-decode.sha256` by running the command
once against the committed pair and copying the two decode lines verbatim into
the file. Commit the file. It holds only the two decode lines, because decode
output is settled after plan 01-02 while the residual and verdict digests move
as plans 01-04 through 01-06 build out the engine.

Write `crates/chrys-cli/tests/digest.rs`. It runs the built binary through
`env!("CARGO_BIN_EXE_chrys")` against the committed pair with `--hash-only`,
parses the four lines, and asserts the two decode lines equal the two lines in
the committed file. Resolve both paths from `CARGO_MANIFEST_DIR` joined to
`../..`. Also assert the report has four lines, that every digest is 64
characters, and that a second run of the same command gives byte-identical
stdout.

Write `.github/workflows/determinism.yml`.

Re-verify the runner labels against GitHub's own runner reference page before
you write them. 01-RESEARCH.md states its own label list is 30-day perishable
and that GitHub changed this landscape twice in eighteen months. If a label has
moved, use the label the reference page lists today and record the change in the
SUMMARY.

Name the workflow `determinism`. Trigger it on `push` and on `pull_request`.
Never use the target variant of the pull-request trigger, because it would run
workflow code with repository write scope against an untrusted branch. Set
workflow-level `permissions` to `contents: read` only.

Job one, `digest`. Use a matrix over six runner labels with `fail-fast: false`,
so one red runner does not hide the others: `ubuntu-24.04`, `ubuntu-24.04-arm`,
`macos-15`, `macos-15-intel`, `windows-2022`, `windows-11-arm`. Put each label on
its own list line. Above the matrix, write a comment recording that
`macos-15-intel` is the last x86-64 macOS label GitHub will offer and that it
retires in August 2027, so a future maintainer is not surprised when it
disappears. Write a second comment recording that Linux and Windows aarch64
runners are standard free runners as of the 2025 and 2026 changelog entries, so
no emulation layer and no self-hosted machine is needed.

Each matrix job checks out the repository, uses the toolchain the
`rust-toolchain.toml` file pins with no override, builds in release, runs
`cargo run -q --release -p chrys-cli -- compare tests/golden/pair-01/base.png
tests/golden/pair-01/candidate.png --hash-only` and redirects stdout to
`digest.txt`, then uploads `digest.txt` as an artifact whose name carries the
matrix label. Set `shell: bash` on the run steps so the redirect behaves the
same on Windows.

Pin every third-party action to a full commit hash, with the human-readable
version in a trailing comment on the same line. A tag is movable, and a movable
action is a code path this repository does not control.

Job two, `agree`. It needs job one, runs on `ubuntu-24.04`, downloads every
artifact into one directory, and compares the six `digest.txt` files. It fails
when any two differ. On failure it prints, for each runner, the runner label and
its four digest lines, and then prints one line per disagreeing label pair, so
the log names which runners disagree and on which of the four digests. On
success it prints the four agreed digests once. Write the comparison as a small
inline bash step, not as a new dependency.

Add a short header comment to the file stating what a red run means: a red
`agree` job is a portability bug in the comparison path, and it is a release
blocker, not a flaky test to retry.

Run `actionlint` on the file if it is installed on this machine. If it is not
installed, say so in the SUMMARY and do not install it as part of this task.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pull request branch to workflow | Untrusted code proposes a change that the workflow then runs. |
| GitHub Marketplace action to workflow | Third-party code runs inside the job with the job's scope. |
| committed digest file to guard | A file in the repository decides whether the local guard passes. |
