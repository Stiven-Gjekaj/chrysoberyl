# Phase 1 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

This file was written after the phase executed, not during it. The register is
not new work: all eight plans carried a `<threat_model>` block, so every threat
below was authored before the code it covers. This audit reads the built tree
and records what it measured. Where a mitigation text no longer describes the
code, that is stated rather than corrected in silence.

Verification depth is ASVS level 1: a grep-level check that each named control
is present in the tree, plus a live run of the guard suite. No deeper trace
was performed, and none is claimed.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| file on disk to decoder | Untrusted bytes cross here. The `image` crate parses attacker-controlled structure across four still formats. | arbitrary file bytes |
| file extension to format selection | The extension is attacker-controlled. The format is decided by content signature, never by name. | file name, file signature |
| command line to file system | A path argument selects which file the process opens. | user-supplied path |
| crates.io to build | Third-party code enters the binary here. | source of 48 crates |
| pull request branch to workflow | Untrusted code proposes a change that CI then runs. | workflow inputs, branch contents |
| GitHub Marketplace action to workflow | Third-party code runs inside the job with the job's scope. | action source at a pinned commit |
| committed digest file to guard | A file in the repository decides whether the local guard passes. | expected SHA-256 digests |
| CPU feature detection to arithmetic path | A library reading CPU flags at run time would silently change what the engine computes. | AVX / SSE / NEON availability |
| platform maths library to reported value | A platform transcendental would make a reported number machine-dependent. | `sin`, `cos`, `cbrt`, `powf` |
| source tree to guard | The guard reads the repository's own source, so a comment or string could hide a real call. | Rust source text |
| shell script to working tree | A script that edits source could destroy uncommitted work. | the developer's working tree |

## Deviations from the register as written

Two mitigation texts describe a tree that no longer exists. Neither weakens a
control; both are recorded so a later reader is not misled by the plan text.

1. **T-01-24 and T-01-SC name `imageproc`.** Plan 01-07 added `imageproc` for
   connected-component labelling. Wave 8 removed it as an architectural breach:
   it dragged `image` and `image-webp` into the format-blind engine and
   delegated the verdict's label ordering to a third party. It was replaced by
   an owned two-pass union-find. Measured: `imageproc`, `empfindung` and
   `delta_e` are absent from every manifest in the workspace. The supply-chain
   surface is therefore smaller than T-01-SC describes, and T-01-24's control is
   no longer "sorted by this project despite the crate" but "there is no crate".
   The removal moved no verdict digest and edited no test.

2. **T-01-01 says `decode_guarded` is the only reader.** That held for phase 1.
   Phase 2 added `chrys-source-animation`, which opens its own `ImageReader` at
   `lib.rs:153`. This audit checked it rather than assume it: all three decoder
   branches set the same limits — GIF at line 184, APNG through
   `PngDecoder::with_limits` at line 193, WebP at line 235. The threat class
   holds across both crates. Phase 2's own security review owns that boundary.

## Limitations of this audit

Stated so no reader credits this file with more than it did.

- **Depth is ASVS level 1.** Each control was confirmed present by reading the
  tree. No end-to-end trace and no boundary-placement analysis was performed.
- **No CVE database was consulted.** `cargo-audit` and `cargo-deny` are not
  installed on this machine, measured directly. T-01-SC rests on the registry
  evidence recorded in `01-RESEARCH.md` (age, downloads, source repository) and
  on pinned `=` versions with a committed `Cargo.lock`. It does not rest on an
  advisory scan, because none was run.
- **The 48 crates in the engine graph were not each re-audited here.** The count
  is measured; the per-crate verdicts come from `01-RESEARCH.md`.
