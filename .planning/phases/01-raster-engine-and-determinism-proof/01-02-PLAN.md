**As a** person who reviews visual changes, **I want to** compare two raster
images and read a structural verdict, **so that** the verdict is byte-identical
on every operating system and CPU architecture.

<!-- planner-discipline-allow: ImageReader -->

<objective>
Widen the tracer's one PNG path to the four raster formats SRC-01 names, and
harden the decode boundary while it is still the only untrusted-input surface in
the project.

Purpose: the decode call site is the whole attack surface of Phase 1. It is
written once, in one place, with limits set on every call, so no later format
adapter can add an unguarded path. Normalization is a determinism input too: an
un-normalized orientation or a premultiplied alpha buffer changes the bytes that
every later hash covers.

Output: a guarded decode entry point, a normalization module, one committed pair
per format, and a decode test per format.
</objective>

| Decision (PROJECT.md) | How this plan honours it |
|---|---|
| No per-thing special case, ever | One `decode_guarded` entry point serves all four formats. The format list is a Cargo feature list, not a branch in the engine. |

  <behavior>
    - `decode_guarded` on a file whose declared dimensions exceed `DecodeLimits`
      returns `RasterError::TooLarge` and the process resident memory does not
      grow by the size of the declared image.
    - `decode_guarded` on a truncated file returns `RasterError::Decode`.
    - `decode_guarded` on a zero-byte file returns `RasterError::Decode`.
    - `normalize_to_rgba8` on an image whose EXIF orientation tag is 6 returns a
      buffer whose width and height are swapped relative to the stored buffer.
    - `normalize_to_rgba8` on a 16-bit-per-channel source returns 8 bits per
      channel, and the same input always gives the same output bytes.
    - Two calls to `RasterSource::load` on the same path return byte-identical
      `Frame::pixels`.
  </behavior>
  <action>
Split the decode path out of `crates/chrys-source-raster/src/lib.rs` into two new
modules, and make the guarded path the only path.

Write `src/decode.rs` with one public function,
`decode_guarded(path: &Path, limits: &DecodeLimits) -> Result<image::DynamicImage, RasterError>`.
It opens the path with `image::ImageReader`, calls `with_guessed_format`, builds
an `image::Limits` from the `DecodeLimits` fields (`max_image_width`,
`max_image_height`, `max_alloc`), calls `set_limits` on the reader, reads the
declared dimensions and rejects them against the limits before decoding, then
decodes. Map every `image` error into `RasterError`. Nothing else in this crate
may call `image::ImageReader`; `Source::load` calls `decode_guarded`.

Write `src/normalize.rs` with `Orientation`, an enum over the eight EXIF
orientation values with a `from_exif_u16` constructor, and
`normalize_to_rgba8(image: image::DynamicImage, orientation: Orientation) -> (Vec<u8>, u32, u32)`.
It applies the orientation transform first, then converts to 8-bit RGBA with
straight alpha, and returns the buffer with its final width and height.
Orientation transforms are integer pixel moves only: no resampling, no
interpolation, no floating-point arithmetic. Document on the function that the
returned buffer is straight alpha and that no `image` crate filter may be
applied to it without an explicit conversion first, because at least one such
filter assumes premultiplied input.

Read the EXIF orientation through the decoder's own metadata accessor rather
than by parsing bytes by hand. If the pinned `image` version does not expose it
for a format, default to `Orientation::Normal` for that format and record the
gap in the SUMMARY; do not add a byte parser in this plan.

Change `Source::load` in `src/lib.rs` to call `decode_guarded`, then
`normalize_to_rgba8`, then build the `Frame`. Add `pub mod decode;` and
`pub mod normalize;`.

Write the unit tests named in the behaviour block in the same commit as the code
they test. Build the malformed inputs inside the tests, in a temporary
directory: a zero-byte file, a file holding the first sixteen bytes of a valid
PNG, and a PNG header that declares dimensions above the limit. Do not commit
those files to `tests/golden/`; they are test state and belong inside the test.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| file on disk to decoder | Untrusted bytes cross here, now across four format parsers instead of one. |
| file extension to format selection | The extension is attacker-controlled and is not trusted; the format is guessed from content. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Denial of Service | `decode_guarded` in `crates/chrys-source-raster/src/decode.rs` | high | mitigate | `set_limits` runs on every reader before decode, with `max_image_width`, `max_image_height` and `max_alloc` from `DecodeLimits`. A grep gate proves the crate root has no unguarded reader. |
| T-01-02 | Denial of Service | declared-dimension handling for TIFF and PNG | high | mitigate | The declared dimensions are checked against the limits before any pixel buffer is allocated. A test builds an over-large declared header and asserts `TooLarge`. |
| T-01-05 | Spoofing | file extension to format mapping | medium | mitigate | `with_guessed_format` reads the content signature. A test renames a PNG to a foreign extension and asserts the content still decides. |
| T-01-06 | Tampering | committed fixture files | low | accept | A fixture is regenerated by a committed generator, so a reader can reproduce the bytes. Plan 01-03 adds a digest guard over the pair the determinism check reads. |
| T-01-SC | Tampering | cargo installs from crates.io | high | mitigate | This plan adds no new crate. It only enables features on `image`, which the Package Legitimacy Audit of 01-RESEARCH.md rates `OK`. No install checkpoint is required. |
</threat_model>
